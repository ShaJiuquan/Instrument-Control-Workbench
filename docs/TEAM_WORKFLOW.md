# 项目角色与协作方式

用户于 2026-10-13 指定本项目按角色协作，主会话担任统筹。
本文补充 AGENTS.md，架构与安全要求仍以 CONSTITUTION.md 为准。

| 角色 | 负责内容 | 交付与边界 |
| --- | --- | --- |
| 统筹（主会话） | 拆任务、排序、分配文件、集成与发布；对用户报告结果 | 维护唯一阶段清单；确认评审问题关闭后提交、干净源码审计、打包和 GitHub 同步 |
| 产品经理 | 用户实验流程、功能优先级、验收标准 | 区分本阶段必须完成和后续增强；描述操作员看到的状态，不凭空补齐物理接线 |
| 架构师 | Core/Application/Infrastructure/App 边界、运行与资源生命周期、数据契约 | 审查暂停、恢复、停止证明、所有权和兼容性；先指出可复现的问题，再决定是否需要重构 |
| 后端 | 领域模型、C# 执行层、设备会话、驱动适配、计划导入与存档 | 保持显式单位、取消和资源占用；真实协议限制留在适配器；不直接改界面布局 |
| 前端 | Avalonia 界面、ViewModel、参数表单、运行状态和操作反馈 | View → ViewModel → Application；明确实际值、设定值和终点目标；不直接调用驱动 |
| 验证测试 | 独立审查、异常路径、回归、模拟和命令行验收 | 覆盖停止失败、暂停、漂移、预算与数据证据；记录真实验证结果和未验收项 |

## 执行流程

1. 统筹给出阶段目标、验收条件、允许修改的文件及依赖。
2. 产品经理与架构师先明确流程和契约；独立只读工作可以并行。
3. 统筹分配互不重叠的文件给后端与前端；共享契约文件指定唯一写入者。
4. 验证测试独立检查实现与风险。发现缺陷时，由统筹安排责任角色修复。
5. 统筹核对最终变更清单、执行必要审计，并从确切提交的干净源码打包。
6. 验证打包后的命令行流程，再提交 GitHub 并确认远端 SHA。汇报已完成内容、证据和缺口。

角色是工作分工，执行器仍是既定的自主 C# 执行层，不引入 OpenTAP 依赖。
当前工具最多支持统筹加三个并发工作代理，因此角色按依赖轮转执行；六个
职责保持独立，不以同时启动数量代替实际交付。代理不会自动获得提交、发布、
实验室操作或扩大文件范围的权力。统筹统一协调集成与对外动作。

## 当前约束

- 仅修改拥有的 `codex/ppms-csharp-platform` 工作树；Rust PPMS 为只读参考。
- 不重复运行没有新证据需要的完整测试。
- 用户已选择先做代码检查；桌面启动和最小窗口视觉验收继续延期。
- SR830 主动交流输出采用显式外部硬件隔离与断开确认，优先适配矩阵卡。
  已有通用矩阵的暂停保留路由/终止恢复基线路由，不能直接当成 AC 断开证明。
  未声明和验证隔离能力、接线、生命周期前，保持主动交流输出禁用。
- 每个阶段可发布成果，但不能把部分迁移宣称为整个 PPMS 目标完成。

## 本阶段实际交付与后续顺序

- 架构师和验证测试独立找出长间隔误超时、暂停目标漂移两项问题。
  统筹修复采样期限，后端修复保持目标的两次恢复校验，补充正反对照回归。
- 产品经理要求先发布可靠执行与数据证据，再提供无需改 JSON 的温度扫描入口。
- 前端确认温度计划结果已有独立视图，现有 I-V 专用图不应套用于温度；下一阶段
  复用 PlanScanValues 和草稿 Apply/Discard 流程，加入共用温度表单及两个类型的 palette。
- 下一阶段原生表单验收：保存重载保留类型/ID/子流程/设置；静态非法配置拒绝；
  编辑时设备不连接；三点模拟运行记录实际温度、确认设定值及索引/总数。
- SR830 主动隔离需后端独立实现能力、声明连接集（包含基线路由）、停机/暂停
  断开证明及恢复，架构师审核后再提供界面。当前 passive 功能不等于主动交流实现。

## 原生温度表单阶段

后端提供仅具备独立配置能力的 Kelvin 控制器只读目录，前端接入共享表单和
两个明确类型的流程节点入口；产品经理审核中文操作说明，架构师审核边界与
身份/精度保留，验证负责人独立覆盖完整编辑、保存、模拟运行、归档与导出。
统筹统一调度构建，避免共享输出目录被并行测试覆盖，再进行发布检查。
后续继续主动 SR830 隔离、更多原生仪器与流程表单和整体迁移；视觉检查继续延期。

## 主动 SR830 原子采集阶段

统筹按独占文件范围整合；后端负责编译、设备组义务和原子执行，架构师负责
行证据、合成与存档验证，前端负责严格配置/计划 JSON 和节点说明，验证角色
独立覆盖漂移、取消、暂停、停止失败及恢复，产品经理审查流程和范围。
主动入口本阶段使用 JSON；原生主动表单、curr_ac 电流推导和自动增益后续实现。
具体契约见 [sr830-active-isolation.md](sr830-active-isolation.md)。
